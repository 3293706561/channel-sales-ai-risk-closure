# 特渠销售经营风险闭环（个人作品集项目）

这是一个可本地运行的销售风险处理演示项目。我关注的不是让 AI 自动管理销售，而是把一条经营异常从发现推进到有人处理、有人复核、结果可回看。

## 演示什么

以华北区域风险为例：

1. 区域经理在驾驶舱确认风险及其数据线索。
2. 区域经理指派整改责任人和截止时间。
3. 一线销售补充已采取的动作、阻碍和需要协同的事项。
4. 一线销售提交人工复核。
5. 区域经理查看整改进度，关闭风险或退回继续整改。
6. 系统保留处理过程和状态变化记录。

风险也可以被标记为误报，但仍会保存原因和历史记录。

## 为什么这样设计

预警只是开始。实际工作里，更重要的是异常有没有被接住、谁负责、何时处理、处理结果能否复查。因此项目把“发现风险”“指派任务”“补充进度”“人工复核”拆成连续操作，而不是让 AI 直接给出结论。

## AI 在哪里参与

当前为 Mock AI，用于演示：从日报提取待确认事实、根据已有风险线索整理核验问题与下一步建议、汇总未关闭风险形成简报草稿。

AI 的输出必须由业务人员确认。它不会自动认定责任、自动关闭风险或绕过复核。Mock 只用于展示输入、输出和边界，不代表真实模型准确率。

## 技术实现

- 前端：原生 ES Module，按页面与接口模块拆分；
- 后端：FastAPI；数据：SQLite；
- 角色：区域经理、一线销售、销售总监；
- 状态：待确认 → 处理中 → 待复核 → 已关闭；
- 验证：包含状态流转、权限、重复提交和 AI 拒答场景的接口测试。

当前前端未使用 React/Vue，目的是先把业务闭环和接口联调跑通。后续迭代会迁移组件化前端，并补足筛选、表单反馈和规则配置。

## 本地运行

双击 `启动全栈项目.bat`，再打开 `http://127.0.0.1:8000`。

演示账号均使用密码 `demo123`：

| 账号 | 角色 |
| --- | --- |
| `north_manager` | 华北区域经理 |
| `east_sales` | 一线销售 |
| `director` | 销售总监 |

推荐按“区域经理 → 一线销售 → 区域经理”的顺序切换角色，完整走完一条协作链路。

## 当前范围

- 使用模拟/脱敏数据，不连接 SAP、CRM、企业微信或真实客户系统；
- AI 功能为本地 Mock；
- 不替代业务审批和责任判断；
- 项目来自销售管理实习场景的观察与抽象，不代表企业实际交付。
